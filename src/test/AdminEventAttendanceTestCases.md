# 관리자 전체 출석 명단 테스트

대상은 `GET /api/admin/event/attendances/all`이다. 요청에 페이지 크기나 검색 파라미터가 없으므로 경계값은 저장된 이벤트 수와 이벤트별 출석 수로 정한다. 이 API에는 명시된 최대 건수가 없다.

## 경계값 분석과 동등 분할

| 조건 | 분할 및 대표값 | 기대 결과 |
| --- | --- | --- |
| 전체 이벤트 수 | 없음 `0`, 한 개 `1`, 여러 개 `2` | `data`에 각각 0, 1, 2개의 이벤트 포함 |
| 이벤트별 출석 수 | 없음 `0`, 한 건 `1`, 여러 건 `2` | `attendances`에 해당 이벤트의 출석만 포함. 0건은 `[]` |
| 이벤트 제목 | 서로 같은 제목 | 이벤트 ID가 다르면 명단을 각각 반환 |
| 동일 회원의 출석 범위 | 한 이벤트, 두 이벤트 | 각 이벤트에 기록된 출석을 모두 보존 |
| 출석 기록의 회원 상태 | 조회 가능한 회원, 조회할 수 없는 회원 | 회원 정보 또는 `탈퇴한 회원`과 학번 `-` 반환 |

## 결정 테이블

| 인증 정보 | 역할 | 저장 데이터 | HTTP | 응답 |
| --- | --- | --- | --- | --- |
| 없음, 잘못된 토큰, 리프레시 토큰 | 해당 없음 | 무관 | 401 | 출석 정보 미포함 |
| 유효한 액세스 토큰 | 일반 회원 | 무관 | 403 | 출석 정보 미포함 |
| 유효한 액세스 토큰 | 관리자 | 이벤트 없음 | 200 | `data: []` |
| 유효한 액세스 토큰 | 관리자 | 이벤트 있음, 해당 이벤트 출석 없음 | 200 | 해당 이벤트의 `attendances: []` |
| 유효한 액세스 토큰 | 관리자 | 이벤트 있음, 출석 있음 | 200 | 이벤트 날짜 내림차순으로 이벤트별 출석 반환 |

## 자동 테스트 범위

| 유형 | 검증 내용 |
| --- | --- |
| 단위 | 저장소를 모킹하여 0·1·2건, 이벤트 ID별 그룹화, 탈퇴 회원 응답, 동일 회원의 복수 이벤트 출석을 검증한다. |
| 통합 | 실제 MySQL에 저장한 이벤트와 출석을 Spring 서비스로 조회해 정렬과 명단 분리를 검증한다. |
| 시스템·기능 | 실제 HTTP 서버에서 관리자 로그인 후 조회하고, 빈 응답에서 데이터가 있는 응답으로 바뀌는 전체 흐름과 JSON 필드를 검증한다. |
| 보안 | 토큰 없음·형식 오류·리프레시 토큰은 401, 일반 회원은 403인지 확인한다. 거부 응답에 명단이 없는지와 관리자 응답에서 회원 비밀번호, 역할, XP가 빠져 있는지도 확인한다. |
| 회귀 | 기존 단일 이벤트 조회의 출석 응답과 존재하지 않는 이벤트의 HTTP 400 및 `EVENT-001`을 확인한다. |
| 성능 | 이벤트 100개와 출석 2,000건으로 예열 3회 후 HTTP 조회 및 JSON 파싱을 20회 측정한다. 로컬 스모크 테스트 기준은 p95 2초 이하다. |
| 동시성 | 별도 트랜잭션으로 출석 1건을 삽입한 상태에서 HTTP 조회 8건을 동시에 시작한다. 커밋 전에는 추가 건이 보이지 않고, 커밋 후에는 정확히 한 건이 보이는지 확인한다. |

## 실행

```bash
./gradlew test --tests '*AdminEventAttendanceUnitTest'
```

통합·시스템 테스트는 로컬 테스트용 MySQL 포트를 지정해야 실행된다. 테스트는 전용 `comaroom_attendance_test` 스키마를 사용하며 Spring 테스트 프로파일로 테이블을 생성하고 삭제한다. MySQL 사용자는 `ATTENDANCE_TEST_MYSQL_USER`와 `ATTENDANCE_TEST_MYSQL_PASSWORD`로 지정한다. 기본값은 `root`와 빈 비밀번호다.

```bash
ATTENDANCE_TEST_MYSQL_PORT=3306 ./gradlew test --rerun --tests 'com.coma.comaroom.event.*'
```
